- **Date**: 2026-08-07
- **Agent**: main session (Phase 2b follow-up — the collapse guard)
- **Task**: Built PRD §5.7's collapse guard as a defect fix ahead of Phase 3, after `initial_prompt` silently destroyed a live 30.5-second dictation down to two words. Also implemented `store_audio`, added `manu history --last`, `guard_ms`, `Transcription`, `DictationState.RECOVERED`, and the guard columns in `history.db`. Merged as PR #7, deployed to the operator's running daemon.
- **Surprise**: **The guard I designed measured the user, and the failure was in the decoder.** The intuitive instrument for "this transcript is too short for the speech" is words per second, and I drafted, specced, tested and defended it that way. An unnamed `advocatus-diaboli` killed it in 400 seconds with an objection I had not seen in three passes over my own draft: words per second divides *how the user talks* by *how long they talked*, while the failure is *where the decoder stopped* — and `faster_whisper.Segment` has carried `start`, `end`, `avg_logprob`, `no_speech_prob` and `compression_ratio` the whole time, with `_decode` joining the texts and dropping every one of them. The signal was already crossing the boundary and being thrown on the floor. Worse, the wrong instrument had a failure mode I had written into the spec as a *feature*: a rate floor cannot judge short audio at all, because word count is an integer and at two seconds the rate quantises to 0.5 w/s **per word** — a genuine one-word "Yes." is the same measurement as a transcript collapsed to one word. So I specified `min_audio_seconds` to exempt short clips, called it a design decision, and only discovered it was arithmetic when the operator said "it's often that I would do a genuine two-second clip." Short dictation is his ordinary case. I had specified a blind spot over the most common input and documented it as a safeguard. The replacement — decoded coverage — is duration-independent, has no false-positive population, and answers the mechanism question that dictionary objection O3 had said was unanswerable from a floor: the collapse is early termination via **prompt echo**, and `initial_prompt = "And how much is this?"` makes the decoder emit exactly that string as the transcript of a 25-second clip, deterministically.
- **Proposal**: For GOTCHAS, three, all promoted this session. (1) **A check written against a *remembered* failure is written against a description.** `verify_guard.py`'s first positive control used a prompt I reconstructed from this repo's own gate-record prose — "a prose prompt collapsed the transcript" — because the prompt itself was never written down. It reproduced nothing, so the script ran the negative control twice, found zero false positives both times, and printed PASS. I nearly reported it. This is the **fourth** instance here of a check that could not fail, after `sentinel-integrity-check.sh` passing on zero agents, the generated index that could not see new records, and that same index reporting zero entries inside records it *could* see. Two rules: record the *input* that produced a failure rather than your account of it, and make the control's own silence an error — the script now exits non-zero when the positive control catches nothing. (2) **Unit tests supply the numbers, so they cannot find a wrong denominator.** §5.7 divided by `TrimResult.retained_seconds` and called it "speech by construction". It is not: `[vad] speech_pad_ms` adds 400 ms of deliberate non-speech per side, which the decoder correctly does not transcribe. Every unit test passed because each one handed in both numbers. Real audio showed the shortest genuine sample reading **62.2%** against a 50% refusal gate — twelve points from withholding a transcript the operator actually said, with the bias scaling *up* as clips get shorter. Corrected, 82.8%. A ratio whose denominator comes from another subsystem is untested until both numbers come from that subsystem. (3) **Run `mypy --strict` after a contract change before believing the suite.** `transcribe()` went `str` → `Transcription` and 337 tests stayed green while `manu transcribe` was broken; two call sites still called `.strip()` on the result and the suite mocks past both. Verified with a positive control by reintroducing the bug: mypy names both lines exactly.
- **Improvement**: **Dispatch the sentinel before writing the spec, not after defending it.** I wrote §5.7, argued it across four PRD sections, wrote 27 tests for it, and *then* dispatched the reviewer — which meant O1 invalidated a spec commit, a test file and a config block that all had to be rewritten. The cost was real but the ordering error is the cheaper lesson: I had reviewed my own draft three times and the confound was invisible to me each time, so the sentinel was never going to be a rubber stamp and treating it as a late formality is what made it expensive. Related and worth stating separately: **check a sentinel's claims against the source before acting on them.** Two of these eight were checked; O1 held, and O2's "the pending file is swept at the next daemon start" was false — `sweep_pending` expires by `retain_days` rather than unlinking on sight. The disposition did not change, which is the useful part: the objection was right for a different reason than the one it led with, and I would have propagated a false fact into the PRD by accepting it wholesale. A sentinel is an instrument, and this repo's standing rule is that instruments fabricate in both directions.
- **Constraint**: Proposed for HARNESS.md — **a verification harness must fail when its positive control does not reproduce the failure**, not merely when the subject misbehaves. Falsifiable: every script under `scripts/` that reports PASS/FAIL has a code path returning non-zero on an unreproduced control, and the gate record states what the control reproduced.
