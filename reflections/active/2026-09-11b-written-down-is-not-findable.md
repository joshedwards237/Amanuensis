- **Surprise**: **The lesson that would have saved the session was written into memory this morning and did not reach me.** Mid-implementation, four config tests failed against source I had just restored from a sabotage run. I read the function, ran `inspect.getsource` on the loaded module, wrapped the callee in a spy to print its arguments, and reproduced it by hand in a scratch directory — six tool calls — before clearing `__pycache__`, which fixed it instantly. That is precisely the failure recorded hours earlier in `verify-a-regression-test-by-breaking-the-code`: CPython invalidates bytecode on a second-resolution mtime, copy-edit-run-restore fits inside one second, and the restored file keeps running its sabotaged bytecode. The fact was true, saved, and correctly described — and buried in the last paragraph of a memory whose one-line index entry is about regression tests. **The pointer that gets loaded is the whole interface to a memory; a fact the description does not mention is a fact nobody will look up.** Second surprise, smaller: adding a third field to `manu status` was the *only* reason two existing fields were found wrong. `mode` was read from the frozen start-up config, so one tray click made it permanently stale, and `model` printed the literal string `auto` while `tiny.en` was loaded. Both were **true about `config.toml` and wrong about the daemon**, which is why neither had ever looked suspicious — the field has a plausible source, the source is accurate, and only a running process disagrees with it.
- **Proposal**: For GOTCHAS, two. (1) **A value can be correct about its source and wrong about its subject.** Any surface answering "what is this process doing right now" — a status verb, a health check, a tray row — must read the value in use, never the configuration snapshot it started from. The tell is that the field is *defensible* in review: it names a real key, reads it correctly, and is wrong anyway. Every setting a UI learns to change mints a fresh instance of this, so the count grows with the feature. (2) **When a memory fails to fire, the fix is the description, not another copy of the fact.** A durable lesson appended to a related memory inherits that memory's trigger, and triggers do not compose — "I just wrote a regression test" and "I am about to run a sabotage loop" are different moments. Split it out with its own description rather than deepening the file it was appended to.
- **Improvement**: **Give the sabotage loop its own memory, addressed to the moment it is needed.** The mechanical rule is one line — clear `__pycache__` between restore and re-run, and treat any sabotage result that contradicts the source as a cache result until proven otherwise — and it has now cost time twice in one day for want of a findable home. More generally: this session's memories that *did* fire were the ones whose description matched the moment. `read-the-fake-before-writing-against-it` fired correctly and paid for itself — `_FakeSoundDevice.query_devices` ignored `kind=`, so `describe_device`'s default-input branch would have reported device 0 as "the system default" and passed against a fake that could not tell the two calls apart. Extending the double *first* is what made the negative control possible at all.
- **Gotcha found in the spec, not the product**: **a recorded open question names the axis you were thinking about, not the one that decides.** PRD §11.6 was written yesterday with three open items, and its second — "a pinned device is wrong when it is absent" — implied validation belonged somewhere, calling `DeviceNotFoundError` at start-up "defensible but not obviously correct". Implementing it decided the opposite: **no** existence check anywhere, at the writer or at `set_device`, because the device set changes while the daemon runs and a check at write time answers a question that is already stale by the time the row is clicked. The recorded question was not wrong, but it was aimed at *where to refuse* when the real axis was *when the answer expires*. Worth expecting at every gate: the entry frames the decision, and framing it is not the same as scoping it.
- **Constraint**: Proposed and added to HARNESS.md — **a status surface reports live state, not the configuration it started with.** Enforcement is honestly `none` today: nothing tests the string `manu status` assembles, because `_status` is a closure inside `_daemon` and cannot be reached without starting a daemon. The mechanical version is a check that the status handler's response contains no `config.` read; the useful version is extracting `_status` so the string can be asserted at all. That extraction is the open item this constraint carries.
